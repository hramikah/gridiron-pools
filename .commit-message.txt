Loser Pool rules: read the points table DOWN the columns

The 32 teams were laid out in a single Bootstrap .row of col-md-3 cells, which
fills left to right, row by row -- so the four cheapest teams sat side by side
on the top row. The printed sheet reads down its columns instead: Cardinals,
Dolphins, Jets, Raiders down the far left, and the value climbing as you move
right.

The grid is now four explicit columns, cut with |batch(per_col) from the same
points-ascending list, so column 1 is the cheapest eight and column 4 the
dearest eight. per_col is a ceiling division rather than a hard 8, so a season
with a different number of teams still balances, and an empty list gets a
message instead of a division by zero.

Also: .loser-points-grid .badge gets a min-width, because one- and two-digit
point values otherwise left the team names on two different left edges down a
column.

Checked at 1200px (four columns of eight) and at 390px (two of eight, then two
more), reading correctly down each column in both.

Also adds add-opener-game.command -- pulls the Wednesday season opener's real
line from The Odds API and adds it to Week 1 in all three pools. Unused if the
game is entered by hand instead; kept because the same thing happens whenever
the opener falls outside the Thu-Wed window.

And publish-week-now.command -- runs the ordinary publish against the LIVE
database on demand, aimed at the COMING Thursday (run today, the plain
publisher picks the week about to end). Dry run first, refuses if that resolves
to a preseason week, backs up, then prints the resulting slate. This is what
put Week 1's 15 NFL and 85 college games up.

And pause-droplet-publish.command / resume-droplet-publish.command -- stop and
start the LIVE site's Thursday publish timer. The publisher only skips a game
it can still SEE in the week, so a college game deleted by hand is simply
re-added on the next run; pausing is the only way to make a hand-pruned slate
stick. Scores keep running either way. The pause script says loudly that the
next week will not publish itself until the resume is run.

Note the existing pause-publishweek.command / resume-publishweek.command target
a launchd agent on the Mac from before the droplet existed. They do nothing to
the live site.
